# juryoku-hikkoshi

Browser physics game: move furniture into a room while gravity rotates.

重力引越: 引っ越し業者として、トラックの荷台から部屋へ家具を運び込む。重力の向きは11秒目から8.5秒ごと（計6回）に上下左右へ変わる。仕様の「最初の10秒は重力を変えない」は初回プレイだけでなく全員共通にしている（日替わりの切替時刻を全員そろえるため）。初回プレイだけ、予告の意味の説明が出る。

公開ページ: https://5umm3r.github.io/juryoku-hikkoshi/

## 遊び方

`index.html` をブラウザで開く（ビルド不要、`file://` で動く。Matter.js 0.20.0 は `vendor/` に同梱）。

- 家具をドラッグして、荷台からドアを通して部屋（正方形）へ運ぶ。横長の画面では荷台が左・ドアが左下、縦長の画面では荷台が上・ドアが左上（ステージ開始時の画面の向きで決まる）
- ロープ固定・解除: PC はダブルクリック、スマホは長押し。どちらも HUD のロープボタンを押してから家具をタップ/クリックでもよい。単なるタップでは固定しない
- ロープは同時に3本まで（外せば戻る）。床・壁・天井・閉じたドアに接している家具だけ固定できる。宙に浮いたままでは固定できない
- 切替3秒前に画面の縁が光り、大きな矢印と「重力が上へ」のような文字で次の向きを予告する
- HUD には残り時間、運び込めた数、見込み額（いま時間切れになったときの請求額）、ロープの残り本数を出す
- 60秒の時間切れ時点で、部屋の中で止まっている家具だけが「運び込めた」扱い
- 結果は「大家さんからの請求書」（運搬報酬 − 被害額）。事故リプレイ、画像シェア、即リトライあり
- 割れた家具は「運び込めた」数にも「全部屋入り」実績にも入らない。荷台の上で起きた被害は請求しない
- 最高額は「今日の現場 No.N」ごと、フリープレイとは別に保存する
- 「今日の現場 No.N」は JST の日付で決まるシード（2026-11-01 が No.1）。家具の順番と重力の変化が全員同じになる

## 初見の人への誘導

初見プレイで分かりにくかった点と、その確認方法は `docs/onboarding-review.md` にまとめた。誘導は遊んだ回数ではなく、そのゲームでの行動で出し分ける（すでに遊んだ人にも出る）。

- タイトル: 長い説明文をやめ、3 コマの図（ドラッグしてドアから部屋へ → 重力が変わる → 止まっていれば報酬）にした
- 画面上の名前: 荷台・ドア・部屋に常に名前を描く
- ドラッグ誘導: そのゲームで最初に家具をつかむまで、荷台の家具に手の印と「ここをドラッグ」を出す
- ゴール誘導: 最初の家具が部屋で止まるまで、部屋の枠を点滅させ、荷台 → ドア → 部屋の経路と「ここへ運ぶ」を描く
- 重力の説明: 最初の切替予告で「家具は矢印の向きへ落ちる」を出す（2 ゲームまで）
- ロープのヒント: 最初の家具が部屋で止まったとき、ロープを一度も使っていなければ、その家具を丸で囲み「長押しでロープ固定」（PC はダブルクリック）を出す
- 結果画面: 金額の列に見出しを付け、報酬の条件と、報酬にならなかった家具の理由（荷台に残った / 部屋の外 / 止まっていない / 割れた）を数で出す

誘導は `Render.draw` の state（`labels`、`guide`）で渡し、ライブのときだけ描く。リプレイとシェア画像には出さない。物理と日替わりの進行には触れていない。

## 方針（参考にした OSS と採った方式）

実装前に Matter.js 公式リポジトリの examples を読んだ。`gyro.js` は `engine.gravity.x/y` を書き換えて重力の向きを変え、`substep.js` は Runner の delta を 1000/600ms に下げて薄い剛体のすり抜けを抑え、`sleeping.js` は `enableSleeping` を使い、どの例も `MouseConstraint`（stiffness 0.2）でつかむ。GitHub で Matter.js のゲーム例も検索したが、ヒットしなかった。そこで本作は、これらの考え方を組み合わせて自前で書いた（コードはコピーしていない）。主な仕組みは次のとおり。

- 時間の進め方: Runner は使わず、1/240 秒の固定ステップを自前のアキュムレータで1フレームに複数回まわす
- 重力の切替: `engine.gravity` を書き換え、全剛体に `Sleeping.set(body, false)` をかける
- つかんでいる間: `beforeUpdate` で重力を打ち消す力を加える。重い家具ほど打ち消しを弱め（sag）、拘束の stiffness も下げる
- すり抜け対策: 外壁を厚くし、`afterUpdate` で速度に上限をかける。拘束は位置を直接動かすので、1サブステップの移動量にも上限をかける。指が家具から 90 以上離れたら手を離す

物理と採点は `src/rules.js`（純粋関数）と `src/sim.js`（Matter のみ、DOM なし）に分けた。描画は記録したスナップショットだけを入力にするので、プレイ中の画面とリプレイは同じ関数で描いている。

ドアは「重力が部屋から荷台の向き（横長は左、縦長は上）を向いている間だけ閉まる」方式にした。ただし家具がドアに挟まっている間は閉めない。

被害は「相対速度 × √(相手との質量比、0.25〜4 に制限)」が家具ごとの閾値を超えた分で計算する。重い冷蔵庫がゆっくり触れる程度（相対速度 0.7 前後）では何も壊れない。重力切替から 4 秒以内に、手を離していた家具が落ちて受けた被害は、切替 1 回ごとに報酬の 15% までに抑える。金魚鉢も、その間は強い衝撃でしか割れない。持ったまま高いところから落とすような雑な扱いには上限をかけない。

## ファイル

| パス | 内容 |
| --- | --- |
| `src/rules.js` | シード乱数、重力列（同じ向きを連続させない）、日替わり番号、被害クールダウン、判定、請求書、実績 |
| `src/sim.js` | Matter のワールド、家具、固定ステップ、被害検出、ロープ、トラック、記録、ステージ進行 |
| `src/render.js` | Canvas 描画（ライブとリプレイ共通） |
| `src/app.js` | 画面遷移、MouseConstraint、タップ/ダブルクリック、ポーズ、結果、リプレイ |
| `src/share.js` | 請求書画像の生成（`document.fonts.ready` を待つ）、Web Share API、画像保存と X 投稿 |
| `src/audio.js` | WebAudio で合成した衝突音・割れる音・予告音 |
| `src/i18n.js` | 英語キーと日本語辞書（デフォルトは ja） |
| `src/storage.js` | localStorage（すべて try/catch）: 最高額、実績、ロープを使ったか、重力の説明を見た回数 |

URL に `?debug` を付けたときだけ、`window.__jh`（自動検証用のフック）を公開する。`tick(ms, n)` で手動フレーム送り、`game` で状態参照ができる。通常のプレイでは公開しない。

## テスト

```sh
npm test   # = node --test test/*.test.js （依存パッケージなし）
```

テストは本体の定数を流用せず、テスト側のリテラル設定で結果を確かめる。対象は次のとおり。

- 重力列: 同じ向きが連続しない、同じシードなら列が一致する
- スリープ: 寝ている剛体が重力切替後に動く
- すり抜け: 速い小物を壁に押し付け続ける、つかんで壁の向こうへ引っ張る
- 判定: 静止判定と部屋内判定
- 被害: 0.5 秒クールダウン、金魚鉢が割れる
- ステージ進行: 切替間隔と 3 秒前予告、最初の 10 秒は切替なし、荷台の上限待ち、請求書と実績
- 採点バランス（`test/review.test.js`）: 4 つのシードで「出てきた家具をすぐ部屋に置く（ロープなし）」が「何もしない」を 3000 円以上上回る。数値は `npm test` の出力に `balance` として出る
- 初見の誘導（`test/onboarding.test.js`）: 部屋で静止した箱 1 個で見込み額がその報酬になる、時間切れ直前の見込み額が最終請求額と一致する、報酬にならなかった理由の数、画面とスクリプトが使う文言キーが ja と en の両方にある、ライブでは荷台・ドア・部屋の名前と誘導を描きリプレイでは描かない、予告に向きの文字が出る
- そのほか: ゆっくり触れても壊れない、荷台の被害は請求しない、ロープ（同時 3 本、宙では不可）、割れた家具の数え方、物理演算から天井ピアノ実績が付く、縦長レイアウト

## 既知の課題 / 次の候補

- 縦長と横長でワールドの配置が違うので、同じ「今日の現場」でも画面の向きが違えば物理の結果は一致しない（家具の順番と重力の列は同じ）
- 日替わりの同一性は、同じブラウザ・同じ操作なら再現する程度。端末間で浮動小数点の結果が完全に一致する保証はない
- 次段階の候補: 動画シェア（MediaRecorder）、45 度重力モード、家具の追加（本棚、観葉植物）
